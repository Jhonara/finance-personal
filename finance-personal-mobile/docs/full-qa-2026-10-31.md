## Recorrido real de interfaz y conciliación

En el emulador se creó QA31_UI Banco (20), se comprobó el nombre requerido y se registró una apertura de 1.000.000 COP. Desde el formulario de gasto se crearon padre QA31_UI Grupo e hija QA31_UI Detalle conservando el importe y la cuenta elegidos.

| ------------------------------------------ | ----------: | ---------: |
| Apertura                                   |   1.000.000 |          0 |
| Gasto en subcategoría, 25.000              |     975.000 |          0 |
| PDF de 78.300, revisión y confirmación     |     896.700 |          0 |
| Ingreso de 50.000 con subcategoría laboral |     946.700 |          0 |

Cada operación aparece una sola vez. El PDF está publicado y enlazado a una única transacción. El gasto agrupado del padre de QA suma 103.300 COP. El ingreso laboral incluye 50.000 de UI y 4.500 del recorrido API; la transferencia no aumenta el ingreso ni el gasto.

La cuenta 21 se preparó por API; desde UI se renombró a QA31_UI Destino editado, desactivó y reactivó conservando saldo y estado final activo. Las programaciones de QA quedaron pausadas o terminadas, sin nuevos registros automáticos futuros.

El selector Android abrió el PDF ficticio: una página y un movimiento de 78.300 COP. Se editaron concepto, cuenta y subcategoría, guardó el borrador y confirmó el gasto. La foto real inicial produjo un borrador incompleto, que se descartó con confirmación. El diagnóstico posterior usa el mismo helper productivo en un paquete aislado sin red. Esa prueba nativa no equivale a volver a seleccionar la foto en la pantalla del APK final.

Perfil y Menú se comprobaron visualmente. El modo Sistema pasó de claro a oscuro con un ingreso de 12.345 aún escrito, conservando importe y contraste de encabezado, panel, secciones y selector. Las regresiones cubren también confirmación abierta, selección, primer plano, cambio de usuario y privacidad.

También se cerró la sesión del emulador con confirmación, se rechazó una contraseña incorrecta con un mensaje claro conservando el correo y se inició sesión correctamente de nuevo. Con fuente del sistema a 1,4, Inicio adaptó sus accesos y Menú apiló Reportes/Presupuestos sin recortar los títulos. Se restauró el tamaño 1,0 y el tema oscuro originales.

El acceso central Nuevo abrió las opciones de gasto, ingreso y transferencia. Tras el nuevo acceso, Continuar borrador recuperó el ingreso ficticio de 12.345 sin contabilizarlo.

Al finalizar se retiró ese borrador ficticio mediante Crear nuevo movimiento; el formulario quedó vacío y no se registró otro ingreso. Se restauraron las animaciones originales del emulador.

## Mejoras pendientes priorizadas

Actualización del 1 de noviembre: las funcionalidades de los puntos 1 y 2 y parte de las comprobaciones del punto 3 se completaron después de este recorrido. Consultar [el cierre de pendientes](pending-features-2026-10-31.md) para contratos, pruebas y entrega actual. Las observaciones siguientes conservan el estado original del informe del 31 de octubre.

1. **P2 — Corregir desde el historial:** la API permite revertir gastos, pero el detalle unificado móvil no expone esa acción. Ingresos y transferencias tampoco tienen una reversión pública general. Diseñar historial y contratos seguros antes de añadir botones o borrados físicos.
2. **P2 — Metas y presupuestos:** faltan contratos públicos para borrar presupuestos, editar/eliminar metas y retirar aportes. Definir el tratamiento financiero e histórico como mejora separada.
3. **P2 — Integraciones y accesibilidad:** completar widget, accesos rápidos, permisos bancarios y TalkBack; probar varias fotos difíciles y PDF escaneados con el APK final.
4. **P3 — Renovación visual posterior:** uniformidad de controles, animaciones, densidad y gesto de selección en gráficos, conservando las reglas financieras verificadas.
5. **P3 — Enlaces durante recreación de Android:** al enviar un enlace externo inmediatamente después de cambiar el tamaño de texto, el cliente de desarrollo mostró una advertencia de navegación y permaneció en Inicio. La navegación interna posterior funcionó. Repetir con el APK final antes de atribuirlo a una ruta de producto o modificar Expo Router.
